# 短片工厂

从动画原片中识别完整故事，生成可编辑的解说稿，全文一次配音，再按实际人物和动作匹配画面，导出无字幕短片。默认先由你确认文案，制作后只做一次画面匹配审核；不自动审稿、改稿、剪配音或根据终审结果重新匹配。

## 使用

Windows、Python 3.12+、FFmpeg / FFprobe。安装 `requirements.txt` 后运行 `python run.py`。本地原声转写与配音时间对齐使用可选的 `requirements-asr.txt`；识别结果用于原片背景或音频时间定位，不作为配音质量门禁。

配置位于 `workspace/config.json`。密钥只保存在私有配置中，不写入故事方案、任务的配音设置快照或测试报告。正式出片需要真实模型和真实 TTS；Mock 仅用于开发测试。

1. 输入本地动画或视频网址、参考文案。数量填 `0` 表示自动发现全部独立故事；填正整数表示最多制作这些数量。
2. 软件分析章节和连续人物事件，生成文案。你可直接编辑、保存、确认、跳过或要求重写。
3. “仅确认文案”保存并确认当前稿；“确认文案并制作”确认当前稿并制作已确认的故事。
4. 整段配音后首次匹配镜头，剪辑并导出。唯一画面审核会留下具体问题和成片，审核不通过不会自动重配或重新收费。

默认原生语速为 **1.1**。全文只提交一次 TTS，配音不拆句、不剪停顿、不为目标时长再次加速。目标片长用于生成文案和显示预测，实际画面完整覆盖返回的音频。旧任务保留原来的音色、模型和语速，以免同一配音重复合成。

## 评论话术

在文案中使用中文 `（）` 或英文 `()`，内容会橙色高亮，例如：女孩冲出走廊（忘记带玫瑰花了），身后的门突然关上。

括号内的话随正文一次朗读，括号符号不读。它不参与故事对象或动作匹配，不会凭空寻找玫瑰花；出现在哪里，就在那段真实配音时间承接相邻剧情画面。可选择原位承接、轻推平移或短停缓动。支持句中多处插话。

编辑草稿会暂存，后台刷新不会覆盖。确认后的正文变化会重新匹配画面；评论画面效果变化复用完整配音。失败的重写保留原稿和已有音视频。

## 原片理解与首次匹配

- 先检测真实章节标题卡，按实际标题帧划分章节；没有明确标题时，重叠扫描全片，再按连续主角和事件链归并。地图、看电视、入睡、求助和警方接待可以属于同一故事，不因转场而拆成新故事。
- 原字幕、已有转写或可用的本地原声识别提供人物关系和动机背景。原声不等于画面证据，也不会逐字翻译成成片文案。没有原声时明确记录可用性。
- 本地切点建立真实镜头目录。每个镜头的首、中、末帧作为独立图片读取，软件绑定源时间；模型只返回镜头和帧 ID，不自行填写秒数。
- 编剧合并镜头为事件，讲清起因、危险、应对和结果，保持人物身份。文案交给你确认，不追加自动审稿和反复重写费用。
- 首次匹配以已确认正文为准，选择真实镜头和动作帧；代码把动作短语的配音时间与源帧绑定。修改正文不会继续沿用旧稿的平均镜头位置。

不同原片独立分析。同源复用按文件内容指纹、模型、提示词及输入设置验证，不根据文件名套用故事。若新章节目录与已有用户稿冲突，原任务保留稿件与编号，提供更正目录，不覆盖编辑或继续为旧错误拆章收费。

## 流畅剪辑与资源

缓慢推近和平移采用平缓起止、双倍输出采样后缩回目标分辨率，避免整数坐标微跳。同一镜头的正文和评论连续运动，不重置缩放。短转场默认约 0.125 秒，上限 0.18 秒。短片不插入仅几帧的闪切来凑镜头。

成片保留源片画幅，采用轻去噪与锐化。内存紧张时降低运动计算的中间采样并限制编码缓存，保留成片分辨率。完整配音文件保持不变，混音只调音量并按设置添加环境音。

## 断点与费用

每个故事、分镜批次、配音和制作阶段分别保存。接口超时或空内容不会清空已完成文案，续跑复用成功批次与完整配音；空内容不能缓存成有效方案，也不能永久锁住制作。

模型返回空内容时记录模型、结束原因和用量。只有明确推理耗尽输出预算时允许一次调整预算的恢复请求，不盲目重放原请求。每次实际返回独立记账，包括空响应。未知单价不会显示为免费。

本机视觉读取和首次镜头匹配已切到 `qwen/qwen3.6-plus`，文案生成保留 `zhenzhen/g5.6-sol`。这些是已配置平台的型号，其他平台需使用各自准确型号和密钥。

## 命令行与产物

```powershell
python cli.py run "D:\videos\source.mp4" --mode semi
python cli.py run "D:\videos\source.mp4" --mode semi --max 1
python cli.py run "D:\videos\source.mp4" --resume <job_id> --max 0
python cli.py report <job_id>
python cli.py render-plan "方案.json"
```

任务保存在 `workspace/jobs/<job_id>/`：`job.json` 保存状态，`analysis/` 保存章节、文案与真实分镜，`clips/<clip_id>/` 保存完整配音、时间轴和 MP4。失败的实际匹配不会冒充通过；已导出文件与问题报告保留。

验证：`python -m pytest`、`python -m ruff check factory tests`。
